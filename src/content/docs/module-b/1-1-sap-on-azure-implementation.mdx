## What the Auditor Checks

The auditor verifies that your organisation has **demonstrated technical capability** in planning, migrating, and running SAP workloads on Microsoft Azure — not just knowledge, but real customer delivery using the SAP-on-Azure service surface (M / Mv2 / Mv3 VMs, Azure NetApp Files, Availability Zones, ExpressRoute, ACSS, Azure Monitor for SAP, HSR, ASCS/ERS clustering).

**Typical questions:**

- Can you show SAP workload delivery on Azure with real customers (greenfield or migration)?
- Which SAP-certified VM families, storage tiers, and management services has your team used in production?
- Do you have reference architectures and signed customer deliverables (HLD / LLD / runbook)?

- [ ] **Azure service mapping** — specific SAP-on-Azure services used per customer — PDF / Excel

<Aside type="tip">
  Case studies should explicitly reference the **SAP product** (e.g. S/4HANA 2023 FPS01), the **SAP
  database** (HANA 2.0 SPS07), and the **Azure services** (M192ms_v2 + ANF + HSR sync across AZ1/AZ2
  + ExpressRoute Direct). Generic "SAP migration to cloud" descriptions are weak evidence.
</Aside>

## Evidence Guidance

### Case Study Structure

Each case study should include:

- **Customer:** "Customer A" (or full name with consent), industry, scale (users / TB).
- **Challenge:** business problem and the trigger (end of HW lease, S/4HANA conversion, etc.).
- **Solution:**
  - SAP products and versions
  - Database (HANA / Oracle / DB2 / ASE) + sizing
  - Azure VM SKUs per tier (e.g. Mv3 for HANA, Edsv5 for app)
  - Storage layout (ANF / Premium SSD v2 / Ultra Disk; volume sizing)
  - HA / DR design (zonal HSR sync + cross-region async; ASCS/ERS; ASR)
  - Network (ExpressRoute SKU, peering, NSG strategy)
  - Operations (ACSS, Azure Monitor for SAP, Azure Backup for SAP HANA, Update Manager)
- **Outcome:** measurable business and technical KPIs (e.g. cutover window &lt; 36 h, RTO &lt; 4 h).
- **Delivery timeline:** weeks from kickoff to go-live, plus hypercare duration.
- **Your team's role:** lead architect / Basis lead / programme management / co-delivery with partner X.

### Architecture Diagrams

Diagrams must clearly show:

- SAP-certified VM SKUs per tier
- Storage layout (data, log, shared)
- Availability Zones and HSR / cluster topology
- Network connectivity (ExpressRoute, peering, firewalls)
- Identity (Entra ID, SAML/OIDC for Fiori SSO)
- Management plane (ACSS, Azure Monitor for SAP, Azure Backup for SAP HANA)

### Capability Statement

A 1–2 page document listing:

- SAP products you've delivered on Azure (S/4HANA, BW/4HANA, ECC, SCM, GRC, SuccessFactors integration, etc.)
- Azure services your team is qualified to deliver for SAP
- Number of completed engagements per product / pattern
- Key team members and their AZ-120 / SAP-side certifications

## Common Gaps

- **Case studies are generic "SAP on cloud":** rewrite to call out the exact SAP product version + Azure VM SKU + HSR design.
- **All case studies are S/4HANA greenfield:** add a brownfield migration or a RISE landing zone to show breadth.
- **Architecture diagrams are high-level only:** add a detailed view with VM SKUs, ANF volumes, and HSR topology.
- **No HA / DR design visible:** add the zonal HSR design and the RTO/RPO commitment.
