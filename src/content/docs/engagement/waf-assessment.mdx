## When to use this

After discovery, before locking the HLD. The WAF assessment surfaces design risks early when the customer can still change direction.

## Pillar weighting for SAP on Azure

SAP workloads have a strong skew. Use this order:

1. **Reliability (HA / DR)** — deep-dive first.
2. **Performance Efficiency** — deep-dive, especially HANA and app-tier sizing.
3. **Operational Excellence** — ACSS, Azure Monitor for SAP, Update Manager, runbook quality.
4. **Security** — Entra ID + PIM + Defender for Cloud + network segmentation.
5. **Cost Optimization** — relevant but secondary on hyper-critical SAP systems.

## Reliability deep-dive

- Availability Zone strategy for HANA primary + secondary
- HSR mode (sync vs async vs multi-target)
- Pacemaker + SBD config; STONITH
- ASCS / ERS cluster topology and ALB floating IP
- File system HA (NFS / ANF, `/sapmnt`, `/usr/sap/trans`)
- Backup strategy — Azure Backup for SAP HANA, log backup interval (typically &le; 15 min)
- DR design — cross-region HSR async, ASR app tier, drill cadence
- Defined RTO / RPO per system, signed by the customer

## Performance Efficiency deep-dive

- VM SKU against the SAP-certified HANA table (PRD specifically)
- Storage layout: data, log, shared on ANF or Premium SSD v2; IOPS / throughput calc
- Accelerated networking enabled on all SAP VMs
- Proximity placement groups for HANA + app tier latency
- DB-host parameter review (HANA, OS, NIC)

## Operational Excellence deep-dive

- ACSS onboarded for the entire landscape
- Azure Monitor for SAP solutions deployed
- Azure Backup for SAP HANA configured + tested
- Azure Update Manager handling OS patching cadence
- Runbook documented for start/stop, patching, backup verification, DR failover/failback

## Security deep-dive

- Entra ID for Fiori SSO + SAML / OIDC
- PIM for Basis admin elevation
- Defender for Cloud + Defender for Servers active
- Network: NSGs, ASGs, private DNS, no public endpoints on SAP systems
- Encryption: Azure Disk Encryption / customer-managed keys; HANA data-at-rest
- Secrets in Key Vault; no creds in scripts

## Cost Optimization deep-dive

- Reserved Instances for production VMs
- Auto-shutdown for dev / sandbox tiers
- Storage tiering (Hot / Cool) for backups beyond 30 days
- Right-sizing review at hypercare exit
